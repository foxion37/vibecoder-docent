# 0042 — 설치 온보딩은 호스트의 내장 질문 도구로 묻고 답한다

Date: 2026-10-07
Status: Accepted. 사용자 요청. ADR 0041 §3("선택 사항을 한 번에 묻기")을 대체한다. 나머지 ADR 0041 결정은 유지한다.

## Context

ADR 0041의 안내는 선택 사항을 글로 늘어놓고 마지막에 한 번 물었다. 사용자는 설치를 묻고 답하는 방식으로 진행하고, CLI든 앱이든 호스트에 내장된 "질문 + 선택지" 기능을 쓰기를 원했다. 그리고 Claude 앱, 터미널, Codex 앱에서 실제로 시험하라고 했다.

터미널에서 확인한 사실(2026-10-07):

- Claude Code 2.1.285는 `AskUserQuestion`으로 한 번에 세 질문(하나는 여러 개 선택)을 선택 화면으로 보여 줬다. 답을 받은 뒤 설치, 서버 켜기, `docent doctor --probe`, 마지막 질문, 보고까지 진행했다.
- Codex CLI 0.153.4 기본 모드에는 차단형 `request_user_input`이 없고 `request_user_input_async`만 있다. 질문이 대화에 글로 나오고, 에이전트는 잠시 기다린 뒤 추천 선택지로 진행했다. `codex --enable default_mode_request_user_input`(개발 중 기능)으로 켜면 차단형 선택 화면이 나온다.

## Decision

1. 결정이 필요할 때마다 호스트의 내장 질문 도구를 쓴다. Claude Code(터미널, Claude 앱)는 `AskUserQuestion`, Codex(CLI, 앱)는 `request_user_input`, 없으면 `request_user_input_async`, omp는 `ask`, Gemini CLI는 `ask_user`다. 도구가 없을 때만 번호 목록을 글로 쓴다.
2. 질문은 확인 결과에 따라 나눈다. 시작 질문(보는 곳, 확인 요청, Jev)은 한 번에, Node.js, omp, 예전 패키지, 예전 서버, 로그인, 휴대폰 공유, 마지막 열기 질문은 해당할 때만 묻는다. 선택지는 2~4개, 추천을 맨 앞에 "(추천)"으로 둔다.
3. 답을 받기 전에는 다음 단계로 넘어가지 않는다. 비동기 질문 도구만 있으면 질문을 보내고 차례를 끝낸다. 기다리다 추천값으로 대신 정하지 않는다.
4. 진행 안내, 질문, 보고는 모두 쉬운 한국어로 쓴다.

## Consequences

- Claude Code에서는 묻고 답하는 설치가 선택 화면으로 진행된다.
- Codex CLI 기본 설정에서는 질문이 글로 보이고 사용자가 채팅으로 답한다. 선택 화면을 원하는 사용자는 Codex의 개발 중 기능을 켜야 한다. README에 적는다.
- 데스크톱 앱(Claude 앱 2.26454.0, ChatGPT 앱 안의 Codex)은 이번에 시험하지 않았다. 독립 Codex 앱은 지원이 끝나 ChatGPT 앱에 들어갔다. 앱 화면을 자동으로 조작하려면 화면 녹화와 손쉬운 사용 권한이 필요해 보류했다. 시험하면 이 기록 아래에 결과를 덧붙인다.
