# 0041 — 링크 하나로 에이전트가 설치하는 온보딩

Date: 2026-10-07
Status: Accepted. 사용자 요청. ADR 0007의 설치 방식은 그대로 두고, 설치를 에이전트에게 맡기는 경로를 더한다. §3(선택 사항을 한 번에 묻기)은 ADR 0042가 대체한다.

## Context

설치 방법은 다섯 가지(Release tgz, GitHub 설치, npx, bunx, macOS 앱 빌드)이고 Node.js 버전, omp 설치와 로그인, 서버 켜기, 휴대폰 공유 같은 설정이 흩어져 있다. 사용자는 설정이 귀찮으니 코딩 에이전트에게 링크를 주고 "설치해줘"라고만 하면 끝나기를 원했다.

## Decision

1. 저장소 루트의 `INSTALL-AGENT.md`가 에이전트용 설치 안내다. 사용자는 이 파일의 GitHub 주소를 에이전트에게 준다. 특정 에이전트 제품에 묶지 않는다.
2. 순서는 Node.js 확인 → omp 확인 → Release tgz 설치 → `docent doctor` 점검 → 서버를 백그라운드로 켜기 → `docent doctor --probe`로 모델 한 번 호출 → 선택 사항을 한 번에 묻기 → 짧은 마무리 보고다.
3. 에이전트는 확인할 수 있는 것을 묻지 않는다. 사용자에게 묻는 것은 선택 사항(브라우저, 터미널, 휴대폰, Jev, macOS 앱) 한 번뿐이고 기본값이 있다. omp 로그인과 비밀값 입력은 사용자가 직접 한다. 에이전트는 키 값을 받거나 파일에 쓰지 않는다.
4. `sudo`, 시스템 서비스 등록, 공개 인터넷 노출은 하지 않는다(ADR 0007·0011). 이미 있는 Node.js 버전 관리 도구를 쓴다.
5. 판단 근거는 `docent doctor [--json] [--probe]`다. Node.js 버전, omp와 채팅 모델 목록, 서버 상태와 제공자별 세션 수, Jev 키 유무, 남은 할 일을 사람용 글과 JSON으로 보여 준다. 모델 호출은 `--probe`일 때만 도슨트와 같은 격리 실행 정책으로 한 번 한다. 필수 항목이 실패하면 종료 코드 1이다.

## Consequences

- 사용자는 링크와 "설치해줘" 한 마디로 설치하고, 직접 할 일은 omp 로그인과 선택 사항 대답뿐이다.
- 링크가 가리키는 안내와 `docent doctor`는 공개 `main`과 Release에 올라가야 동작한다. Release보다 안내가 앞서면 오래된 패키지에는 `docent doctor`가 없다.
- 서버 자동 시작은 여전히 없다. 컴퓨터를 다시 켜면 사용자가 `docent`를 실행한다.
