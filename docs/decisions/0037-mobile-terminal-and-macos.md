# 0037 — 같은 도슨트 서버에 모바일, 터미널, macOS 화면을 연결한다

Date: 2026-10-06
Status: Accepted. 사용자 승인. ADR 0014의 사용자 표면을 웹앱으로 한정한 결정을 대체한다.

## Context

사용자가 모바일, Ghostty와 Kaku에서 쓰는 터미널, macOS 앱을 각각 요청했다. 모바일은 설치형 웹앱(PWA), macOS는 기존 웹 화면을 담는 데스크톱 앱을 선택했다. 기존 설명 생성, 학습 기억, 요청 중단과 바로잡기는 서버에 이미 모여 있다.

## Decision

1. **설명 엔진과 저장소는 기존 서버 하나다.** 세 화면은 같은 HTTP 인터페이스와 서버 발급 스레드, 요청 식별자를 쓴다. 별도 모델 호출, 클라우드 저장소, 플랫폼별 학습 기억 복제는 만들지 않는다. 같은 서버와 프로필에 연결해야 같은 문답을 본다.
2. **모바일은 PWA다.** 600px 이하에서는 세션, 작업 내용, 대화를 한 화면씩 보여 준다. 설치 정보, PNG 아이콘, 홈 화면 실행, 화면 키보드와 안전 영역을 지원한다. 모바일은 연결된 컴퓨터가 켜져 있어야 설명을 받을 수 있다. 브라우저가 제공하는 설치 기능은 iOS Safari와 Android Chromium에서 방식이 다르다.
3. **모바일 HTTPS는 Tailscale Serve다.** `docent-mobile`은 기본적으로 상태만 확인하고, `--enable`을 명시해야 사설 HTTPS 공유를 설정한다. 기존 다른 서비스의 443 설정이나 공개 Funnel이 있으면 덮어쓰지 않고 거부한다. 웹앱의 기존 Tailscale IPv4 공유 스위치와 Serve의 HTTPS 설정은 별개다. 사설망 사용자도 신뢰할 수 있어야 하며 프로필은 인증 수단이 아니다.
4. **오프라인에는 안내만 제공한다.** 서비스 워커는 개인 기록이 없는 오프라인 페이지 하나만 CacheStorage에 저장한다. 전사와 문답, API 응답을 오프라인 캐시에 넣지 않는다. API 응답에는 `no-store`를 사용한다. 기존 입력 초안의 localStorage 정책은 유지한다.
5. **터미널은 하나의 Node 클라이언트다.** Ghostty와 Kaku 전용 확장을 따로 만들지 않는다. 선택, 질문, 답 스트림, 중단과 바로잡기를 기존 서버로 보낸다. 원문의 터미널 제어 문자는 실행되지 않게 처리한다. 서버는 별도로 켜며 클라이언트 종료가 서버 종료를 뜻하지 않는다.
6. **macOS는 Electron으로 웹 화면을 재사용한다.** 렌더러의 Node 접근은 끄고 샌드박스를 사용한다. 로컬 도슨트의 `/api/health`로 기존 서버를 식별해 재사용하고, 없으면 앱이 서버를 시작한다. 앱이 시작한 자식 서버만 종료할 수 있다. 서버는 정상 종료 때 자신이 시작한 모델 프로세스도 종료한다. 기존 서버와 사용자 설정을 임의로 끄거나 바꾸지 않는다. 실행 중 자산을 CDN에서 받지 않는다.
7. **배포물은 분리한다.** npm 패키지는 웹 서버와 터미널, 모바일 연결 명령을 제공한다. macOS 앱에는 Electron과 서버 실행에 필요한 로컬 파일을 포함한다. 서명 없는 로컬 `.app` 빌드와 Apple 서명 및 공증을 받은 외부 배포는 구분하며, 후자는 인증서와 별도 배포 승인이 필요하다.

## Consequences

- 기존 웹앱과 같은 문답, 깊이, 모델 선택을 공유하므로 화면마다 설명 동작이 달라지지 않는다.
- 모바일의 최초 연결에는 Tailscale 설치와 HTTPS 설정이 필요하다. 기존 Funnel 설정을 자동으로 끄지 않는다.
- macOS 앱이 시작한 서버를 쓸 때는 앱 종료 후 모바일도 연결할 수 없다. 상시 접속은 별도 실행 중인 도슨트 서버를 재사용하는 방식이다.
- Electron 빌드는 npm 웹 서버 배포보다 크다. macOS 서명과 공증은 별도 운영 항목이다.
- 터미널은 터미널 입력과 너비 계산, 모바일은 실기기 키보드와 설치, macOS는 서버 수명과 외부 링크 차단을 각각 검증해야 한다.
